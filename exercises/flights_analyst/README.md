# Флайты ANALYST — средний тир (аналитик с опытом)

Между базовыми (`flights/`) и жёсткими (`flights_hard/`). Задачи **реалистичные и
честные**: сложность в том, чтобы собрать многошаговый запрос, а не угадать скрытый
подвох. Такое реально дают аналитику на работе.

База: `demo`, схема `bookings`.

## Что здесь отрабатывается (навыки реального аналитика)
- **Time series:** группировка по `date_trunc('month', ...)` + `lag` для «к прошлому периоду».
- **Сегментация/бакеты:** `CASE WHEN ... THEN 'ярлык'` + двухуровневая агрегация.
- **Доля от общего:** `SUM(...) OVER ()` — процент вклада.
- **Метрики-отношения:** load factor, средний чек — деление двух агрегатов (помни про `100.0`).
- **Обход сложных связей:** используем view `timetable` вместо ручного `flights → routes`.

## Полезное по схеме
- Выручка живёт в `segments.price` (сегмент = перелёт по билету).
- `segments.flight_id → flights.flight_id`; `segments.ticket_no → tickets`.
- `tickets.book_ref → bookings` (там `total_amount`, `book_date`).
- Продано мест: `boarding_passes` (по flight_id); вместимость: `seats` (по airplane_code).
- **`timetable`** уже содержит `flight_id`, `arrival_airport`, `departure_airport`, `airplane_code` —
  бери его, чтобы не воевать с `routes` (валидность/дни недели).
